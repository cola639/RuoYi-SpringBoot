在 Spring Boot 中，如果你的项目有 **多个子 Library（子模块），而子 Library 里又有多个孙 Library（子依赖）**，Spring Boot 通过 *
*Maven 或 Gradle** 来管理这些依赖关系。

---

## **1. Spring Boot 如何处理多层依赖？**

### **✅ 依赖传递（Transitive Dependency）**

在 **Maven/Gradle** 中，**如果你的项目 A 依赖 B，而 B 又依赖 C，那么 A 也会间接依赖 C**。  
Spring Boot 主要通过 **Maven 的依赖管理（Dependency Management）和传递依赖（Transitive Dependency）** 机制来处理。

### **✅ 依赖冲突（Dependency Conflict）**

如果不同的模块（子 Library）**引入了不同版本的相同依赖**（比如 `jackson-databind:2.13.4` 和 `jackson-databind:2.14.0`
），Spring Boot 通过：

1. **优先使用最近声明的版本**
2. **Spring Boot BOM（Bill of Materials）自动管理**
3. **Maven 的 `dependencyManagement` 显式指定版本**

---

## **2. 由谁决定最终使用的孙依赖？**

最终决定**用哪个版本的孙依赖（C 依赖）**，取决于以下几个因素：

### **🔹 1. Maven 依赖解析顺序**

**Maven 解析依赖的顺序如下（最近声明优先）**：

1. **项目 `pom.xml` 里直接声明的版本**（最高优先级）
2. **`dependencyManagement` 里声明的版本**
3. **父 POM（Spring Boot BOM）提供的版本**
4. **传递依赖（Transitive Dependency）里最先解析到的版本**

📌 **示例：**

```xml

<dependencies>
    <dependency>
        <groupId>com.example</groupId>
        <artifactId>libA</artifactId>
        <version>1.0</version>
    </dependency>
    <dependency>
        <groupId>com.example</groupId>
        <artifactId>libB</artifactId>
        <version>2.0</version>
    </dependency>
</dependencies>
```

- **`libA` 依赖 `jackson-databind:2.13.4`**
- **`libB` 依赖 `jackson-databind:2.14.0`**
- **如果 `libB` 在 `libA` 之后声明，最终会用 `jackson-databind:2.14.0`**

### **🔹 2. Spring Boot BOM（依赖管理）**

Spring Boot 提供了 **BOM（Bill of Materials）**，自动管理 Spring 生态相关依赖的版本。  
如果你使用 Spring Boot，**BOM 会决定默认使用哪个版本的孙依赖**。

📌 **Spring Boot BOM 示例**

```xml

<dependencyManagement>
    <dependencies>
        <dependency>
            <groupId>org.springframework.boot</groupId>
            <artifactId>spring-boot-dependencies</artifactId>
            <version>3.0.0</version>
            <type>pom</type>
            <scope>import</scope>
        </dependency>
    </dependencies>
</dependencyManagement>
```

- Spring Boot **自动管理 Spring 相关依赖的版本**，你可以**不用写版本号**
- **如果你的孙依赖在 BOM 里，Spring Boot 版本优先**

### **🔹 3. `dependencyManagement`（项目自己控制版本）**

如果你的 `pom.xml` 里使用了 `dependencyManagement`，你可以手动指定某些库的**全局版本**，所有子 Library 都会使用这个版本。

📌 **`dependencyManagement` 示例**

```xml

<dependencyManagement>
    <dependencies>
        <dependency>
            <groupId>com.fasterxml.jackson.core</groupId>
            <artifactId>jackson-databind</artifactId>
            <version>2.13.4</version> <!-- 强制使用这个版本 -->
        </dependency>
    </dependencies>
</dependencyManagement>
```

**这个 `dependencyManagement` 版本优先于 Spring Boot BOM 版本。**

## **3. 依赖冲突排查工具**

如果你的项目有多个 **子 Library，孙 Library 的版本冲突**，你可以用以下方法排查：

### **🔹 1. `mvn dependency:tree`（查看依赖树）**

在项目根目录运行：

```bash
mvn dependency:tree
```

**示例输出（缩略版）：**

```
[INFO] com.example:myapp:jar:1.0
[INFO] ├─ com.example:libA:jar:1.0
[INFO] │  └─ com.fasterxml.jackson.core:jackson-databind:jar:2.13.4
[INFO] ├─ com.example:libB:jar:2.0
[INFO] │  └─ com.fasterxml.jackson.core:jackson-databind:jar:2.14.0
```

这里可以看到 **`jackson-databind` 有两个不同版本**，最终哪个版本会被使用**取决于解析顺序**。

### **🔹 2. `mvn dependency:tree -Dverbose`**

如果想查看**哪个依赖决定了最终的版本**：

```bash
mvn dependency:tree -Dverbose -Dincludes=com.fasterxml.jackson.core:jackson-databind
```

它会显示**哪个 Library 强制使用了哪个版本**。

### **🔹 3. `mvn dependency:analyze`**

如果想查看**是否有未使用或重复的依赖**：

```bash
mvn dependency:analyze
```

---

## **4. 解决依赖冲突的方法**

### **方法 1：使用 `dependencyManagement`**

手动指定一个**全局一致的版本**，防止子 Library 之间版本不一致。

```xml

<dependencyManagement>
    <dependencies>
        <dependency>
            <groupId>com.fasterxml.jackson.core</groupId>
            <artifactId>jackson-databind</artifactId>
            <version>2.14.0</version>
        </dependency>
    </dependencies>
</dependencyManagement>
```

📌 **优点**：所有子 Library 都会使用 `2.14.0`，避免版本冲突。

### **方法 2：使用 `exclusions` 排除不想要的版本**

如果某个 Library 依赖了错误的版本，你可以手动排除：

```xml

<dependency>
    <groupId>com.example</groupId>
    <artifactId>libA</artifactId>
    <version>1.0</version>
    <exclusions>
        <exclusion>
            <groupId>com.fasterxml.jackson.core</groupId>
            <artifactId>jackson-databind</artifactId>
        </exclusion>
    </exclusions>
</dependency>
```

📌 **优点**：避免子 Library 引入错误的版本。

### **方法 3：调整 `pom.xml` 依赖顺序**

如果两个子 Library 依赖了不同版本的同一个孙依赖，**Maven 解析时会优先使用最先声明的版本**。  
你可以调整 `pom.xml` 里 `dependency` 的顺序，确保正确的版本优先。

---

## **5. 结论**

| **情况**                            | **谁决定最终的孙依赖版本？**                                   |
|-----------------------------------|----------------------------------------------------|
| **项目 `pom.xml` 直接声明的版本**          | **最高优先级**                                          |
| **`dependencyManagement` 里声明的版本** | **优先于 BOM 和传递依赖**                                  |
| **Spring Boot BOM**               | **如果没有 `dependencyManagement`，Spring Boot 默认版本生效** |
| **传递依赖（最近声明的优先）**                 | **如果没有显式指定，Maven 选择最近声明的版本**                       |

✅ **Spring Boot 通过 BOM 管理 Spring 生态依赖版本**  
✅ **如果多个子 Library 依赖不同版本的孙 Library，Maven 解析顺序决定最终版本**  
✅ **使用 `dependencyManagement` 或 `exclusions` 解决依赖冲突**

这样，你就可以完美管理 **Spring Boot 多层 Library 的依赖关系！🚀**
